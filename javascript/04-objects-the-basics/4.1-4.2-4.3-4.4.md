# 4.1: Objects
- objects are used to store keyed collections of various data.
- a `property` is a `key: value` pair.
- `key` (also known as `name` or `identifier`) can be a string or a symbol.
- `value` can be anything.

```js
let obj = new Object();    // "object constructor" syntax
let obj = {};              // "object literal" syntax

let obj = {
    key1: value1,
    "multiword name": value2,
    key3,                       // same as key3: key3
};
```

- `delete` is used to remove a property
```js
delete obj.key;
```

- the dot access can be used with single word key names.
- the square brackets should be used with multiword key names.
- the square brackets should be used with calculated key names.

```js
let x = obj.keyName;
let x = obj["key name"];
delete obj["key name"];

let k = "calculated key";
let x = obj[k];
delete obj[k]; 

let obj = {
    [k]: value1,
    [k + "any expression"]: value2, 
}
```

- `key` can be any string (including preserved names: for, while, ...) or a symbol.
- other types are converted to string.
- we can not set the `__proto__` key to a non-object value. assignments to other types are ignored.
- any property can be accessed. non-existing properties returns `undefined`. no errors.
- check if the key exist using the `in` operator.
- comparing against `undefined` is not enough to check the existing of a key. because the key can exist but stores the value `undefined`.
```js
if ("key" in obj) {}

let k = "key";
if (k in obj) {}
```

- `for..in` loop is used to iterate over the keys of an object
```js
for (let k in obj) {}
```

- the order of keys in objects: integer properties are sorted at the top, then others appear in creation order.
- integer property: a string that can be converted to and from an integer without a change.
```js
const isIntegerProperty = String(Math.trunc(Number(stringKey))) === stringKey;
```



# 4.2: Object references and copying
- objects are stored and copied by `reference`;
- primitive values are copied by `value`;

## comparison by reference
- two objects are equal if they are (if the reference) the same object.
```js
let obj = {};
let obj2 = obj;
obj == obj2;    // true
obj === obj2;   // true

let anotherObj = {};
anotherObj == obj;      // false
anotherObj === obj;     // false
``` 

- for comparisons with `<`, `>`, `<=`, and `>=` or for a comparison against a primitive, objects are converted to primitives.

- a side effect of storing objects as references is that a `const` object can be modified.

## cloning and merging, `Object.assign`
- coping an object creates one more reference to it.
- `Object.assign(dest, ...sources)` can be used to clone an object.
- it copies the properties of all sources into `dest` and returns it as a result.
- if the copied property name already exists, it gets overwritten.

```js
const obj = {};
const clone = Object.assign({}, obj);
```
- the `spread operator` can also be used to clone an object:
```js
let clone = {...obj};
```

## nested cloning
- also called `deep cloning` or `structured cloning`.
- the `structuredClone` method:
    - can clone most data types such as objects, arrays, primitives.
    - supports circular references.
    - functional properties are not supported.
```js
let clone = structuredClone(obj);

// error
structuredClone({
  f: function() {}
});
```



# 4.3: garbage collection

## reachability
- the main concept of memory management in Javascript is `reachability`.
- `reachable` values are those that are accessible or usable somehow.
- `reachable` values are guaranteed to be stored in memory.
    - `root` values: a base set of inherently reachable values, that cannot be deleted. for example:
        - the current executing function, its local variables and parameters.
        - other functions on the current chain of nested calls, their local variables and parameters.
        - global variables.
        - others, including internal values as well.
    - any other value is considered reachable if it is reachable from a root by a reference or by a chain of references. for example:
        - `g` is a global object `const g = {};`
        - `g.a = {};` and `g.a.b = {};`
        - both `a`, `b` and `g` are reachable: `g` is a root (global), `a` and `b` are reachable from a root

## garbage collection
- `garbage collector`: is a background process in the js engine that monitors all objects and removes those that have become unreachable.

### internal algorithms:
- the basic garbage collection algorithm is called `mark-and-sweep`.
- the following `garbage collection` steps are regularly performed:
    - the garbage collector takes roots and marks (remembers) them.
    - then it visits and marks all references from them.
    - then it visits marked objects and marks their references.
    - all visited objects are remembered, so as not to visit the same object twice in the future.
    - …and so on until every reachable (from the roots) references are visited.
    - all objects except marked ones are removed.

### optimizations:
- different engines implement different tweaks and techniques.
- some of the optimizations:
    - `generational collection`: objects are split into two sets: “new ones” and “old ones”. In typical code, many objects have a short life span: they appear, do their job and die fast, so it makes sense to track new objects and clear the memory from them if that’s the case. Those that survive for long enough, become “old” and are examined less often.
    - `incremental collection`: if there are many objects, and we try to walk and mark the whole object set at once, it may take some time and introduce visible delays in the execution. So the engine splits the whole set of existing objects into multiple parts. And then clear these parts one after another. There are many small garbage collections instead of a total one. That requires some extra bookkeeping between them to track changes, but we get many tiny delays instead of a big one.
    - `idle-time collection`: the garbage collector tries to run only while the CPU is idle, to reduce the possible effect on the execution.



# 4.4: Object methods, `this`
- objects are usually created to represent entities of the real world.
- `actions` are represented by functions in properties.
- a function that is a property of an object is called its `method`.
```js
// function expression
const obj = {};
obj.method = function() {} 

// method shorthand
const obj = {
    method() {}
}

// pre-declared function
function actionFunction() {}
obj.method = actionFunction;

```
- `object-oriented programming - OOP`: writing code using objects to represent entities.
- OOP is a big thing, an interesting science of its own. How to choose the right entities? How to organize the interaction between them? That’s architecture, and there are great books on that topic, like “Design Patterns: Elements of Reusable Object-Oriented Software” by E. Gamma, R. Helm, R. Johnson, J. Vissides or “Object-Oriented Analysis and Design with Applications” by G. Booch, and more.

## `this` in methods
- methods need to access the information stored in the object.
- to access the object, a method can use the `this` keyword.
```js
const obj = {
    property: "value",
    method() {
        console.log(this.property)
    }
}
```
- it is also possible to access the object without `this` by referencing it via the outer variable.
- but such code is unreliable.
- if we decide to copy user to another variable, `anotherObj = obj` and overwrite `obj` with something else, then it will access the wrong object.
```js
const obj = {
    property: "value",
    method() {
        console.log(obj.property);
    }
}
```

## `this` is not bound
- it can be used in any function, even if it is not a method of an object.
- the value of `this` is evaluated during the run-time, depending on the context.
```js
function func() {
    console.log(this.prop);
}
```
- if `obj.func()` is called then `this` is `obj` during the call of `func`.
- calling without an object:
    - in strict mode: `this` is `undefined`.
    - in non-strict mode: `this` is the global object (`window` in the browser).
```js
function func() {
    console.log(this.prop);
}

func(); // undefined
```

## Arrow functions have no `this`
- arrow functions are special.
- they do not have their own `this`.
- if we reference `this` from an arrow function, it is taken from the outer context.



## example:
- The value of this is one for the whole function, code blocks and object literals do not affect it.
```js
function makeUser() {
  return {
    name: "John",
    ref: this
  };
}

let user = makeUser();

alert( user.ref.name ); // Error: Cannot read property 'name' of undefined
```

```js
function makeUser() {
  return {
    name: "John",
    ref() {
      return this;
    }
  };
}

let user = makeUser();

alert( user.ref().name ); // John
```
