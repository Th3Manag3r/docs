# 4.5: Constructor, operator `new`
- `{...}` syntax allows to create one object
- many similar objects can be created using `constructor functions` and the `new` operator.

## constructor function
- they technically are regular functions.
- There are two conventions though:
    - they are named with capital letter first.
    - they should be executed only with `new` operator.
- when a function is executed with `new`:
    - a new empty object is created and assigned to `this`.
    - the function body executes.
    - the value of `this` is returned.
- the main purpose of constructors is to implement reusable object creation code.
- any function can be used as a constructor except arrow functions as they don't have `this`.
- the capital letter first is a common agreement to make it clear that a function is to be run with `new`.
```js
function Obj(arg) {
    // this = {};   (implicitly)
    this.arg = arg;
    // return this; (implicitly)
}

const obj = new Obj("value");
```
- if we have many lines of code all about creation of a single complex object, we can wrap them in an `immediately called constructor function`.
- this constructor can't be called again. it is not stored anywhere.
```js
const obj = new Function() {
    this.prop = "value"
    // ... other code
    this.prop2 = "value2"
}
```
- we can omit parentheses after `new` but is a bad coding style
```js
const obj = new Obj();  // good
const obj = new Obj;    // bad
```


## constructor mode test: `new.target`
- inside a function, to check whether it was called with `new` or without it, we can use the special property: `new.target`.
- `new.target`:
    - is `undefined` if the function was called without `new` (in regular mode).
    - equals the function itself if it was called with `new` (in constructor mode).
```js
function Obj() {
    console.log(new.target);
}
Obj();      // undefined
new Obj();  // function Obj { }
```
- we can make both `new` and regular calls do the same:
```js
function Obj() {
    if (!new.target) return new Obj();
    // ... code
}

// these are the same now
const obj = Obj();
const obj = new Obj();
```

## return from constructors
- usually constructors don't have a `return` statement.
- `this` is automatically returned.
- if there is a `return` statement:
    - if `return` is called with an object, the object is returned instead of `this`.
    - otherwise the `return` is ignored.

## methods in constructor
```js
function Obj(arg) {
    this.prop = arg;
    this.method = function() {
        console.log("text: " + this.prop);
    }
}
```
- a `class` is a way to create complex objects.



# 4.6: optional chaining `?.`
- this is a recent addition to the language.
- old browsers may need `polyfills`.
- the `?.` operator stops the evaluation ("short-circuit") if the value before `?.` is `null` or `undefined` and returns `undefined`.
- the variable before `?.` must be declared.
- other variants:
    - `?.()`: used to call a function that may not exist.
    - `?.[]`: used to access properties using brackets instead of dot. including array elements.
- `?.` is used for safe reading and deleting, but not writing.
- `?.` can't be used on the left side of an asignment.



# 4.7: symbol type
- by specification, only 2 primitive types may serve as object property keys: `strings` and `symbols`.
- other types are converted to strings.

## symbols
- a `symbol` represents a unique identifier.
- `symbols` are guaranteed to be unique.
- a description (a symbol name) can be given to symbols upon creation. mostly useful for debugging purposes.
- 
```js
const id = Symbol();
const id = Symbol("id");
const id2 = Symbol("id");

id == id2 // false
```
- symbols don't auto-convert to a string
```js
const id = Symbol();
alert(id);              // error
alert(id.toString());   // works
```
- `symbol.description`: used to get the description
```js
const id = Symbol("desc");
id.description;     // desc
```

## hidden properties
- `symbols` allow us to create `hidden properties` of an object that no other part of code can accidentally access or overwrite.
- because we use `symbols` instead of `strings` there will be no conflict between our code and other code.
```js
const obj = {
    prop: "val",
};
const id = Sumbol("id");
obj[id] = "idVal";

// another code (another lib, third party code, ...etc)
const id = Symbol("id");
obj[id] = "idVal";
```
- `symbols` in an object literal:
- we need the value of the variable `id` as a key, not the string "id"
```js
const id = Symbol("id");
const obj = {
    [id]: "value"
}
```
- `symbolic properties` are skipped by `for..in` loop and `Object.keys(obj)`, `Object.values(obj)`and `Object.entries(obj)`.
- `Object.assign()` copies both string and symbol properties.

## global symbols
- there exists a `global symbol registry`.
- we can create symbols in it and access them later.
- it guarantees that repeated accesses by the same name return exactly the same symbol.
- symbols inside the registry are called `global symbols`.
- application-wise, accessible everywhere symbols.
- `Symbol.for(name)`:
    - returns a symbol by name.
    - it is used to read a symbol from the registery, the symbol is created if not found.
- `Symbol.keyFor(symbol)`:
    - returns a name by global symbol
    - returns `undefined` for non-global symbols.
```js
const id = Symbol.for("id"); // if the symbol did not exist, it is created.
const readId = Symbol.for("id");
id == readId; // true

const name = Symbol.keyFor(id); // id
const name = Symbol.keyFor(readId); // id
const sym = Symbol("sym");
const name = Symbol.keyFor(sym); // undefined
```
- all symbols have the `description` property.

## system symbols
- there exist many `system symbols` that js uses internally.
- these are called the `well-known symbols`

# 4.8: object to primitive conversion
- there is no conversion to `boolean`, all objects are `true`.
- there exist only `numeric` and `string` conversions.

## hints:
- there are 3 variants of type conversion. they are called `hints`.
- these are:
    - `string`:
        - for an object-to-string conversion.
        - example: `console.log(obj)`, `anotherObj[obj]`
    - `number`:
        - for an object-to-number conversion.
        - example: `obj - 5`, `+obj`
    - `default`:
        - occurs in rare cases when the operator is not sure what type to expect.
        - example: `obj1 + 2`, `obj == "string"`, `obj == 123`, `obj == symbol`
- `<`, `>`, `<=`, `>=` can work with both strings and numbers too, but they use the `number` hint not `default` for historical reasons.
- all built-in objects except `Date` implement `default` the same way as `number`. 
- to do the conversion:
    - js calls `obj[Symbol.toPrimitive](hint)` if such method exist.
    - otherwise if the hint is `string`, try calling `obj.toString()` or `obj.valueOf()` whatever exists.
    - otherwise if the hint is `number` or `default`, try calling `obj.valueOf()` or `obj.toString()` whatever exists.
- if `obj[Symbol.toPrimitive]` exists, it is used for all hints and no more methods are needed.
- `[Symbol.toPrimitive]` must return a primitive or there will be an error.
- `toString`/`valueOf` must return a primitive or the returned object value is ignored.
- if `toString` does not exist or it returns an object instead of a primitive then call `valueOf`.
- if `valueOf` does not exist or it returns an object instead of a primitive then call `toString`.
- by default a plain object has:
    - `toString`: returns `[object Object]`.
    - `valueOf`: returns the object itself.
- the primitive-conversion methods can return any primitive type, they do not necessarily return the `hinted` primitive.
- if necessary for further calculations, the resulting primitive is also converted.
