# 5.1: methods of primitives
- primitives are a single value, not multi-value objects.
- in order to allow access to methods and properties of primitives, a special `object wrapper` that provides the extra functionality is created, and then destroyed.
- there is a different `object wrapper` for each primitive type: `String`, `Number`, `BigInt`, `Boolean` and `Symbol`. and they provide different sets of methods.
- primitives can provide methods, but they still remain lightweight. 
```js
// str is a primitive (string);
const str = "value";
// a special wrapper object (that provides string methods) is created.
// the method runs.
console.log(str.toUpperCase()); // VALUE
// the special object is destroyed
```
- constructors `String`, `Number`, `Boolean` are for internal use only.
- in js it is possible to explicitly create wrapper objects for primitives. examle: `const x = new Number(5)`.
- but it is highly unrecommended.
- things will not work as intended in several places if we do so:
    - `typeof` will return `object`. 
    - objects are always `true`.
- using the same functions without `new` is totally fine, they just convert a value to the corresponding type.
- `Symbol` and `BigInt` are not constructors, they cannot be called with `new`.
- `null` and `undefined` are special primitives, they have no corresponding `wrapper objects` and provide no methods. they are `the mose primitive`.
```js
const zero = 0;
const zeroObj = new Number(0);
const zeroNumber = Number(0);

typeof zero;        // number
typeof zeroObj;     // object
typeof zeroNumber;  // number

if (zero) {}        // falsy, for code will not execute
if (zeroObj) {}     // truthy, for code will execute
if (zeroNumber) {}  // falsy, for code will not execute
```
- in `strict mode` writing into a `wrapper object` throws an error.
```js
'use strict'
const x = 5;
x.test = "test"; // error
```



# 5.2: numbers
- double precision floating point numbers.
- stored in 64-bit format IEEE-754.

## many ways to write a number
- underscores `_`:
    - can be used as a separator.
    - syntactic sugar, makes the number more readable.
    - js engines ignores underscores between digits.
    - writing underscores before the first digit or after the last one results in an error;
```js
const n = 1000000;
const n = 1_000_000;
const n = 1_000_000_;   // error
const n = _1_000_000;   // error
```
- the scientific notation `e` or `E`:
    - `aEb = a * 10^b`
    - `a` can be any valid base-10 number, including decimals and negatives.
    - `b` must be an integer, including negatives.
```js
const n = 2e3;      // 2000
const n = 2.1E3;    // 2100
const n = -2.1e-3;  // -0.0021
const n = .1E-3;    // 0.0001
const n = 0x2E4     // error, 0x2 is not base-10, it is a hex (base-16)
```
- hex, binary and octal numbers:
    - `hex`: starts with `0x` or `0X`, uses digits `0-9` and letters `a-f` or `A-F`. 
    - `oct`: starts with `0o` or `0O`, uses digits `0-7`.
    - `bin`: starts with `0b` or `0B`, uses digits `0-1`.
```js
const h = 0xFF;     // 255
const h = 0Xff;     // 255
const h = 0xfF;     // 255

const o = 0o12;     // 10
const o = 0O12;     // 10

const b = 0b11;     // 3
const b = 0B11;     // 3
```

## some methods
- to call a method directly on an integer, `..` two dots must be used.
- becuase js syntax implies the decimal part after the first dot.
```js
5..toString();      // 5
(5).toString();     // 5
5.3.toString();     // 5.3
(5.3).toString();   // 5.3
0..toString();      // 0
.0.toString();      // 0
```
- `num.toString(base)`:
    - returns a string representation of `num` in `base` numeral system.
    - base can vary from `2` to `36`. the default is `10`.
    - `36` is the maximum for base. it uses `0-9` and `a-z`.
    ```js
    const n = 255;
    n.toString(10);     // 255
    n.toString(16);     // ff
    n.toString(8);      // 377
    n.toString(2);      // 11111111
    ```
- rounding:
    - `Math.floor(n)`:
        - rounds down.
        - `3.1` to `3.9` becomes `3`.
        - `-3.1` to `-3.9` becomes `-4`.
    - `Math.ceil(n)`:
        - rounds up.
        - `3.1` to `3.9` becomes `4`.
        - `-3.1` to `-3.9` becomes `-3`.
    - `Math.round(n)`: rounds to the nearest integer.
        - `x.5` rounded up/toward the `+∞`
        - `3.1` to `3.4` becomes `3`.
        - `3.5` to `3.9` becomes `4`.
        - `-3.1` to `-3.5` becomes `-3`.
        - `-3.6` to `-3.9` becomes `-4`.
    - `Math.trunc(n)`: removes any thing after the decimal point (not suported by IE)
        - same as `Math.floor` for positive numbers.
        - same as `Math.ceil` for negative numbers.
    - rounding to the `n-th` digit after the decimal:
        - multiply and divide: `Math.round(num * 10^n) / 10^n`.
        ```js
        // rounding to the 2nd digit after the decimal point
        const num = 12.1234;
        const rounded = Math.round(num * 100) / 100;  // 12.12
        ```
        - `num.toFixed(n)`:
            - rounds `num` to n digits after the decimal point.
            - rounding rules are same as `Math.round()`.
            - returns a string.
            - if the decimal part is shorter than required, zeros are appended to the end. 
        ```js
        // rounding to the 2nd digit after the decimal point
        const num = 12.1234;
        const rounded = num.toFixed(2);  // "12.12"
        ```

## imprecise calculations
- because a number is represented in 64-bit format IEEE-754:
    - some numbers cannot be represented exactly.
    - there are two zeros: `-0` and `+0`.
        - `-0 === +0` is `true`.
        - `Object.is(-0, +0)` is `false`.
        - `1/0` is `Infinity`, `1/-0` is `-Infinity`.
        - `1/Infinity` is `0`, `-1/Infinity` is `-0`.
        - `Math.sign(-0)` is `-0`, `Math.sign(0)` is `0`.
        - `Object.is(Math.sign(-0), -0)` is `true`.
        - `Math.round(-0.1)` is `-0`.
        - `Math.trunc(-0.1)` is `-0`.
        - `String(-0)` is same as `String(0)` which is `"0"`

## `isFinite` and `isNaN`
- `isNan(value)`:
    - converts `value` to a number and tests it for being `NaN`.
    - `value === NaN` returns `false`, `NaN` does not equal anthing including itself.
- `isFinite(value)`:
    - converts `value` to a number and returns `true` if it is a regular namber. i.e. not `NaN`, `Infinity` or `-Infinity`.
    - can be used to validate whether a string value is a valid regular number.
```js
isNaN("");      // false - number("") is 0
isNaN("s");     // true - number("s") is NaN

isFinite("");   // true
isFinite("s");  // false
```
- `Number.isNaN(value)` and `Number.isFinite(value)`:
    - more strict versions.
    - they don't auto-convert their argument into a `number`.
    - `Number.isNaN(value)`: returns `true` if `value` is of type `number` and it is `NaN`. otherwise returns `false`.
    - `Number.isFinite(value)`: returns `true` if `value` is of type `number` and it is not `NaN`, `Infinity` or `-Infinity`. otherwise returns `false`.
```js
Number.isNaN("test");       // false
Number.isNaN("str" / 5);    // true

Number.isFinite(123);       // true
Number.isFinite(Infinity);  // false
Number.isFinite(10 / 0);    // false
Number.isFinite("123");     // false
```

## comparison with `Object.is`:
- it almost exactly the same as `===`.
- `Object.is()` differ in two edge cases:
    - it works with `NaN`.
    - zeros `0` and `-0` are different.
    ```js
    Object.is(NaN, NaN);    // true
    Object.is(0, -0);       // false
    ```

## `parseInt` and `parseFloat`
- numeric conversion using a `+` or `Number()` is strict. If a value is not exactly a number, it fails.
- `parseInt` and `parseFloat` read a number from a string until they can't.
- spaces at the beginning or at the end of the string are ignored.
- `parseInt(value, radix)` returns an integer.
    - `radix`: an optional second argument. the default value is `10`.
    - `radix`: the value should be between `2-36`. other wise it returns `NaN`.
- `parseFloat(value)` returns a floating-point number.
- when no digits could be read, they return `NaN`.



## 5.3: strings
- the internal format for strings is always `UTF-16`, it is not tide to the page encoding.
- quotes:
    - `single` and `double` quotes
        -  are the same.
        - the string cannot span multiple lines.
    - `backticks`:
        - allows to embed any expression into the string.
        - allows the string to span multiple lines.
        - `tagged templates`: `backticks` allows to specify a `template function` before the first `backtick`.
            - the first argument of the tamplate function is an array of string values.
            - the remaining arguments are the expressions.
    ```js
    const singleQuote = 'single quote';
    const doubleQuote = "double quote";
    const backticks = `backticks ${singleQuote}`;

    function func(strArray, ...args) {
        console.log(strArray);
        console.log(args);
    }

    func`one ${1} two ${2}`; // ["one ", "two ", ""]; [1, 2];
    ```
- the `length` property has the string length.

## Special characters
- starts with a backslash `\` which is the `escape character`.
    - `\n`: line feed (LF). can be used to create multiline strings with single/double quotes.
    - `\r`: carriage return (CR).
    - `\'`, `\"`, `` \` ``: quotes.
    - `\\`: backslash.
    - `\b`, `\f`, `\v`: backspace, form feed, vertical tab.

## accessing characters
- the first character starts from the zero position.
- `str[pos]` or `str.at(pos)` can be used to get character at position `pos`.
- with `str.at(pos)`, `pos` can be negative. i.e. `-1` is the last position ...etc.
- `str[pos]` can work with negative positions, it returns `undefined`.
- `for..of` can be used to iterate over the characters.

## strings are immutable
- it is impossible to change a character in a string.
- `str[0] = "c"` throws an error.

## methods
- `str.toLowerCase()` and `str.toUpperCase()`: to change the case.
- `str.indexOf(subStr, pos)`:
    - searches for `subStr` starting from the position `pos`.
    - `pos` is optional, the default value is `0`.
    - returns the position where the match was found or `-1` if nothing can be found.
    - to get all occurrences, we can run `indexOf` in a loop.
- `str.lastIndexOf(subStr, pos)`:
    - same as `indexOf` but starts the search from the end of the string.
    - it would list the occurrences in the reverse order.
- `str.includes(subStr, pos)`:
    - returns `true` if `subStr` is found starting from the position `pos`. otherwise returns `false`.
    - `pos` is optional. the default value is `0`.
- `str.startsWith(subStr)`: returns `true` if `str` starts with `subStr`.
- `str.endsWith(subStr)`: returns `true` if `str` ends with `subStr`.
- `str.slice(start, end)`:
    - returns the part of the string from `start` to (but not including) `end`.
    - `end` is optional. if absent then `slice` goes till the end of the string.
    - negative values are possible for both `start` and `end`.
    - `start` cannot be greater than `end`. otherwise an empty string is returned.
- `str.substring(start, end)`:
    - same as `slice`.
    - but `start` can be greater than `end`.
    - negative values are not supported. they are treated as zero.
- `str.substr(start, length)`:
    - returns the part of the string from `start` with the given `length`.
    - `length` is optional. if absent `substr` goes till the end of the string.
    - `start` can be negative.
    - resides in the `Annex B` of the spec.
        - it means that only browser-hosted js engines shuld support it.
        - and it is not recommended to use it.
        - in practice, it is supported everywhere.
- `str.codePointAt(pos)`: returns a number representing the code for the char at `pos`.
- `String.fromCodePoint(code)`: creates a char by its numeric code.

## comparing strings
- as mentioned before strings are compared character-by-character in alphabetical order.
    - a lowercase letter is always greater than the uppercase.
    - letters with diacritical marks are out of order.
- the right algorithm to do string comparisons is more complex than it may seem, because alphabets are different for different languages.
- the browser needs to know the language to compare.
- modern browsers support the internationalization standard [ECMA-402](https://www.ecma-international.org/publications-and-standards/standards/ecma-402/).
- it provides a special method to compare strings in different languages, following their rules.
- `str.localeCompare(str2)`: returns an integer.
    - returns a negative number if `str` is less than `str2`.
    - returns a positive number if `str` is greater than `str2`.
    - returns `0` if they are equivalent.
    - the complete signature is: `str.localeCompare(str2, locales, options)`. see the spec or mdn.
