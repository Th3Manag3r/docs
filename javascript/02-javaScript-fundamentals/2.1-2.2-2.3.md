# 2.1: The `script` Tag

## the `type` attribute
- HTML4 required a script to have a `type` attribute.
```js
<script type="text/javascript">
    alert( 'Hello, world!' );
</script>
```

- it is not required any more.
- the modern HTML standard totally changed the meaning of the `type` attribute. now it can be used for JavaScript modules. 
```js
<script type="text/javascript">
    alert( 'Hello, world!' );
</script>
```

## the `language` attribute
- meant to show the language of the script.
- no need to use it, JS is the default.

## comments around `script`
- hide js code from old browsers that did not know how to process the `script` tag.
```js
<script type="text/javascript"><!--
    alert( 'Hello, world!' );
//--></script>
```

## external scripts
- if `src` is set the script content is ignored.
- the benefit of a separate file is that the browser will download it and store it in cache.
```js
<script src="/path/to/script.js"></script>
<script src="https://example.com/script.js"></script>
<script type="text/javascript">
    alert( 'Hello, world!' );
</script>
```



# 2.2: Code Structure

## Statements
- syntax constructs and commands that perform actions.
- can be separated with a semicolons.

## semicolons
- may be omitted in most cases (not always) when a line break exists.
- e.g. : js does not assume a semicolon before square bracets [].
- `automatic semicolon insertion`: js interprets the line break as an implicit semicolon.

## comments:
- nested comments are not supported.



# 2.3: The modern mode, "use strict"

- JS evolved without compatibility issues.
- new features added while old functionality didn't change.
- any mistake or an imperfect decision got stuck in JS forever.
- until 2009 - ECMAScript 5 (ES5) appeared.
- `ES5` added new features and modified existing ones.
- to keep the old code working most such modifications are off by default.
- `"use strict"` a special directive used to explicitly enable them 

## use strict
- can be written at the beginning of a script or a function.
- must be at the top. only comments may appear above it. 
- there is no way to cancel `use strict`.
- in classes and modules `use strict` is automatically enabled.
