# 2.4: Variables
- `let`, `const` and `var`

## variable naming
- the name must contain only letters, digits, or the symbols `$` and `_`.
- the first character must not be a digit.
- `camelCase` is commonly used.
- names are case sensitive.
- non-latin letters are allowed but not recommended.
- must not be a reserved name.

## An assignment without `use strict`
- it was possible to create a variable by a mere assignment withlot using `let`.
- this still works if we do not use `use strict`.
- this is a bad practice and would cause an error in strict mode.

## uppercase constants
- capital-named constants are only used as aliases for hard-coded values.
- for constants calculated at run time we do not use capital-named constants.



# 2.5: Data Types
- JS is a `dynamically typed` language.
- there exist data types but variables are not bound to any of them.
- we can put ant data type in a variable.
- there are 8 basic data types:
    - 7 primitives: `number`, `bigInt`, `string`, `boolean`, `null`, `undefined`, and `symbol`
    - 1 non-primitive: `object`. 

### Number
- represents integers and floating point numbers.
- special values:
    - `Infinity`:
        - represents the positive mathematical Infinity.
        - greater than any number.
        - it is the result of `1/0`
    - `-Infinity`:
        - represents the negative mathematical Infinity.
        - less than any number.
        - it is the result of `-1/0`
    - `NaN`:
        - represents a coputational error.
        - a result of an incorrect or an undefined mathematical operation.
        - it is sticky, any further mathematical operation on `NaN` returns `NaN`.
        - the only exception: `NaN ** 0` is `1`;
- Mathematical operations are safe: Doing maths is “safe” in JavaScript. We can do anything: divide by zero, treat non-numeric strings as numbers, etc. and the script will never stop with a fatal error (“die”). At worst, we’ll get NaN as the result. 

### BigInt
- `number` can not safely represent integer values larger than `(2^53)-1` or less than `-(2^53)-1`.
- `number` represents numeric values using the IEEE 754 double-precision 64-bit floating-point format.
- `bigInt` represents integers (not floats) of arbitrary length.
- a `bigInt` value is created by appending `n` to the end of an integer.

### String
- simple quotes: `"double"` and `'single'`.
- `` `backticks` ``: can be used to embed variables and expressinos into a string. `` `string: ${var}` ``.

### Boolean
- `true` and `false`.

### null
- a special type that contains only the value `null`.
- `null` in JS is a reerence to a non-existing object or a null pointer.

### undefined
- a special type that contains only the value `undefined`.
- it means that "value is not assigned".
- the default initial value for unassigned things.

### symbol
- used to create unique identifires for objects.


## the `typeof` operator
- returns a strin with the type name.
- `typeof null; // object` is an officially recognized error/bug in `typeof` that is kept for compatibility.
- `typeof alert; // function` is a special intentional rule, not a bug.
- `typeof value` is same as `typeof (value)`.
```js
typeof undefined;                           // undefined
typeof 123; typeof NaN; typeof Infinity;    // number
typeof 123n;                                // bigint
typeof "string";                            // string
typeof true;                                // boolean
typeof null;                                // object
typeof Symbol("id");                        // symbol
typeof Math;                                // object
typeof alert;                               // function
```



# 2.6: Interaction: alert, prompt, confirm
- the mini-window with the message is called a `modal window`.
- `modal` means the user can't interact with the rest of the page until they have delt with the window.
- `confirm`: returns `true` or `false`.
- `prompt`:
    - returns the entered value, or `null` if canceled.
    - in `IE` always supply defaultValue or the string `undefined` will be inserted into the prompt.
```js
alert("Message");

```



# 2.7: Type Conversions
- most of time, operators and functions automatically converts values to the right type.
- e.g.: `alert` converts any value to a `string`, math operations converts values to `number`s.

## string convertions
- `String(value)`; explicit conversion to a `string`.
- implicit `symbol` convertion to `string` is not allowed.
```js
String(undefined);      // "undefined"
String(null);           // "true"
String(true);           // "true"
String(false);          // "false"
String(NaN);            // "NaN"
String(Infinity);       // "Infinity"
String(122n);           // "122"
String(Symbol("id"));   // "Symbol(id)"
// ...etc
```

## numeric convertions
- `Number(value)`; explicit conversion to a `number`.
- happen automatically in mathematical functions and expressions.
- a `symbol` can not be converted to a `number`.
```js
Number(undefined);  // NaN
Number(null);       // 0
Number(true);       // 1
Number(false);      // 0
```
- `string` to `number`:
    - whitespaces are trimmed from the start and end.
    - if the remaining space is empty, the result is `0`.
    - otherwise a number is read from the string.
    - an error gives `NaN`.
```js
Number("    ")      // 0
Number("")          // 0
Number("  232 ")    // 232
Number("  23.2 ")   // 23.2
Number("  23 2 ")   // NaN
Number("  23 A ")   // NaN
```

## boolean convertions
- `Boolean(value)`; explicit conversion to a `boolean`.
- `undefined`, `null`, `NaN`, `0`, `0n`, and `empty strings` becomse `false`
- other values including `symbol`s becomes `true`
