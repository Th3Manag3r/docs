# 2.8: Basic operators, maths
- an `operand` is what an `operator` is applied to.
- an `operator` is
    - `unary` if it has a single `operand`.
        - the unary negation `-x`
        - `!x`, `typeof x`, `++x`, `x--`, ...etc.
    - `binary` if it has two `operand`s.
        - the subtraction operand `x-y`.
    - `ternary` if it has three `operand`s.
        - js has only one ternary operator: the `conditional operator`.
        - `condition ? expression1 : expression2`

- the binary `+`: if any of its operands is a string, the other one is converted to a string too. the result is the concatenation of the two strings.
- other arithmetic operators work only with numbers and always convert their operands to numbers.
- the unary `+`: `+x` is same as `Number(x)`.
- all operators in JS return a value 
- assignment `=` is an operator and returns the assigned value
- comma `,` operator: allows to evaluate several expressions and returns the result of the last one
- `bitwise operators` convert their operands to a signed 32-bit integers before operating on them.
    - all operations happen within the 32-bit range
    - `AND &` is useful for checking if a bit is set, `x & flag`
    - `AND &` is useful for unsetting a bit, `x & ~flag`
    - `OR |` is useful for setting a bit (bit masking), `x | flag`
    - `XOR ^` is useful for toggling a bit, `x ^ flag`
    - `XOR ^` has an interesting properties: `a ^ a` gives `0`, `a ^ 0` gives `a`
    - `left shift <<`: `a << x` gives `a * 2**x`
    - `right shift >>`: approximately divides by 2. 
    - if `x` is an odd integer: `(x >> 1) << 1` gives `x - 1`
    - `>>` is called `sign-propagating/arithmetic right shit`, it preserves the sign
    - `>>>` is called `zero-fill right shit`, it does not preserve the sign
    - numbers get converted to integeres. `5.9` -> `5`
    - `x.y | 0` gives `x`

## Operator precedence and associativity
- operators with `higher precedence (priority)` executes first.
- parentheses override any precedence (priority). 
- within operators of the same precedence, JS groups them by associativity:
    - `left-associativity` (left-to-right): `a op1 b op2 c` is interpreted as `(a op1 b) op2 c`.
    - `right-associativity` (right-to-left): `a op1 b op2 c` is interpreted as `a op1 (b op2 c)`.

# 2.9: Comparisons
- all comparison operators return a boolean.

## string comparison
- JS uses a `dictionary` or `lexicographical` or `Unicode` order.
- strings are compared letter-by-letter

## comparison of different types
- when comparing values of different types, JS converts them to numbers.

## strict equality
- `===` checks the equality without type conversion.
- `x === y` gives false if `x` and `y` are of different types.

## Comparison with null and undefined
- for a strict equality check these values are different.
- for a non-strict equality:
    - `null` equals `undefined` i.e. `undefined == null` gives `true`.
    - they do not equal any other value.
    - `undefined` is incomparable to any value, it returns false for all comparisons other than `undefined == null`.
    - for math and other comparisons (`<`, `>`, `<=`, `>=`) `null` and `undefined` are converted to numbers.
    ```js
    null === undefined  // false
    null == undefined   // true
    null == 0           // false
    null > 0           // true
    null >= 0           // true
    ```

## Comparison with NaN
- any comparison involving `NaN` returns `false`
